# belFER — code review, 2026-11-21

A full review of belFER after the CP-SAT solver was removed (`1e7a8f9`).
Every source file was read in full, not as a diff, split into five areas:
FET pipeline, domain and checker, API and database, importer, frontend. On top
of that, a separate review of today's own changes (`origin/main..HEAD`).
Nothing was changed by the review itself.

**Status of each finding:**
- **Verified**: reproduced or traced by hand in this session, against the code
  or the local database (changes rolled back).
- **Confirmed**: the reviewer traced the code path; not re-run here.
- **Plausible**: the code allows it; whether the data or timing triggers it
  is not shown.

Findings that two reviewers reached independently are merged and say so.
IDs are per area: **F** FET pipeline, **D** domain and checker, **A** API and
database, **I** importer, **U** frontend.

Open items that were already known (G2, G5, G7, the tuition pupil clash, and
so on) are in [OPEN_ITEMS.md](OPEN_ITEMS.md) and not repeated here.

## F — FET pipeline (solver/)

- **F1 (medium). A stop hides complete weeks that broke a rule.**
  `PlanGenerator.scala:115-117`. If any worker was stopped, only stopped
  workers are ranked. Three complete-but-rejected weeks plus one wedged worker
  and a Stop report "placed 432 of 1331", never which rule the full weeks
  broke. Fix: rank complete-but-rejected above stopped, or return both.
  Confirmed.
- **F2 (medium). `--read` maps FET's answer by re-exporting.**
  `SolveCli` `readFet`; `LessonLineRepository.findForSchool` has **no
  `ORDER BY`** (verified). Activity numbers are positional. Any edit between
  `--fet` and `--read` maps FET's activity N to a different lesson, and the
  checker reports violations FET never made. RUNLOG runs read back straight
  after exporting with no edits, and R11 reproduced R10 exactly, so past runs
  stand. Fix: write each activity's own reference into its `<Comments>` and
  read the mapping from the file, or order deterministically and hash.
  Confirmed.
- **F3 (medium). A week is saved against data that changed during the run**
  (with A2). `PlanGenerator.scala:141-146`. Blocks edited mid-run are saved
  against indices that no longer exist; a deleted line makes the save fail
  and the whole search is lost as an SQL error. Fix: record a data version at
  load and refuse or flag the save if it moved. Plausible.
- **F4 (medium, test gap). The test guarding against surviving FET processes
  cannot fail.** `FetRunnerSpec.scala:62-69` writes its marker inside the
  directory that is deleted. The stop path, the answer ranking and the
  progress regexes are untested. Confirmed.
- **F5 (low). A stop that outlasts 60 s ends as a crash**, not as `Stopped`:
  `FetRunner.scala:249` calls `exitValue()` unconditionally. Confirmed path.
- **F6 (low). A timeout throws away FET's diagnosis**, since it raises before
  reading `difficult_activities.txt` (`FetRunner.scala:246-248`). "0 min" is
  shown for timeouts under a minute. Confirmed.
- **F7 (low). "No timetable file" and `Rejected` drop FET's own words**
  (`FetRunner.scala:374-378`). Plausible.
- **F8 (low). FET can outlive the JVM.** No `--timelimitseconds` backstop is
  passed, and the container is unnamed, so nothing can kill it after the
  client dies (`FetRunner.scala:70-72`, `226-237`). Plausible.
- **F9 (low). Failed generations are never logged**; only `getMessage` is
  kept (`PlanGenerationRuns.scala:146-147`). Confirmed.
- **F10 (low). Workspace cleanup fails silently**, leaving full `.fet` files
  with staff names under `~/.belfer/fet/run-*`. The docker form runs as root
  on Linux (`FetRunner.scala:193-196`). Plausible.
- **F11 (low). Stop is only heard while FET runs.** A stop pressed during
  load, check or save is ignored and the plan is saved; a worker finishing as
  the stop lands is discarded (`PlanGenerationRuns.scala:132-139`). Confirmed.
- **F12 (low). A whole-class lesson with a hard specialist requirement can be
  given a half-size specialist room**, which R3b then rejects
  (`FetExport.scala:503-505`). Confirmed in code.
- **F13 (low). A cancelled start can leave a run stuck as "running"**
  (`PlanGenerationRuns.scala:97-113`; needs `IO.uncancelable`). Plausible.
- **F14 (low). Class-day spread edge cases.** No range gets nothing written,
  yet R17 still enforces it; spread 0 with a load not divisible by 5 runs FET
  for minutes and then rejects everything; a huge value overflows
  (`FetExport.scala:307`, `ClassDays.scala:45`). Fix: Validation flags a
  spread no range can meet, and the setting is capped at the slot count.
  Verified.
- **F15 (low). A cohort group is named for a non-optional subject that has
  attendance rows**, so the file names a student set it never declares. FET
  rejects the file, and with a spread set the exporter throws
  (`FetExport.scala:573-576`, `632-634`). Verified.
- **F16 (low). `subgroups()` duplicates the student-structure naming**; it
  is recomputed up to three times per class, the `dayRange` helper looks
  everything up three times, and one comment claims equal loads "until
  attendance is entered" (false). Confirmed.
- **F17 (low). SolveCli:**
  - `--generate --limit/--doubles/--rooms` saves the altered week as the
    school's current plan, while the new usage text says "nothing is saved"
    (verified);
  - several modes at once silently run one (verified);
  - `--limit` and `--doubles` also apply to `--sheet`, giving wrong lengths;
  - the loader and config are built twice.
- **F18 (nit). Dead code:**
  - `LessonRef.CrossClass`, never constructed (verified);
  - `FetRunner.Config.container` and `.installed`;
  - `FetImport.Placed.length`;
  - `PlanGenerationRuns.Run.fiber`, written and never read;
  - `FetSeed.parse`, used by tests only; nothing replays a stored seed, so

- **F19 (nit). Comments that are now false:**
  - `PlanGenerator.scala:18-29`: "synchronous for now";

  - `FetTuningSpec.scala:127` slices wrongly (`take(j)`);

## D — Domain and checker (domain/)

- **D1 (high, latent; found by two reviewers). R3c rejects every legal week
  in which a subject's room requirement is soft.** `PlanCheck.scala:242-252`
  with `FetImport.scala:118-119`. The exporter lets a soft requirement use
  ordinary rooms; R3c demands the kind. Fix: carry hard/soft on `Scheduled`.
  Confirmed (probe).
- **D2 (medium; found by two reviewers). R10 judges religia/etyka per class,
  while S2 and FET work per half or subgroup.** `PlanCheck.scala:194-202`.
  - *Today:* religia last for half 2 and first for half 1 is legal, nobody
    waits, and R10 rejects it.
  - *With attendance:* the exporter drops the edge rule so a mid-day hour
    stays possible. R10 still demands first or last, and religia and etyka at
    the same hour also trip R1.
  - `PlanCheck.notChecked` reuses the code "R10" for a different rule.

  Confirmed (probe).
- **D3 (medium, latent). R17 measures a half, while the exporter bounds each
  attendance group.** Once attendance is entered for both optional subjects,
  a week where no pupil's spread exceeds the limit can fail R17. The
  underlying issue is the same as D2: the checker's unit is the half, the
  exporter's is the FET subgroup. Fix: give PlanCheck the subgroups.
  Confirmed.
- **D4 (high). S3 is not checked at all.** RULES §6 says "indirectly through
  R1", which is wrong. `FetImport.scala:147-161` takes the unit's class
  occupancy from the first group's time only, and the teaching entries carry
  no classes. A group at a different hour, with its classes booked elsewhere,
  passes everything. FET is told the rule, so this is about the checker's
  independence. Fix: a rule that all groups of a unit block share day and
  start. Verified.
- **D5 (medium). R3b, R3c and R3d skip lessons with no room.** An activity
  given no allowed rooms gets none from FET and is saved roomless
  (`PlanCheck.scala:237-256`). Confirmed (probe).
- **D6 (medium). No bounds check on day or hour.** A double at positions 7–8
  of an 8-slot day, or a lesson on day 6, passes; R12 can never fire on
  in-range data (`PlanCheck.scala:137`). Confirmed (probe).
- **D7 (low). R7 counts, it does not match.** One block placed twice and
  another never placed passes. The save then throws a unique-index error
  instead of rejecting (`PlanCheck.scala:78-83`). Confirmed (probe).
- **D8 (medium). `Validation.teacherHours` leaves out individual tuition**,
  so the teacher-load check and the Walidacja table understate
  (`Validation.scala:316-321`). Confirmed (probe).
- **D9 (medium). `blocksAcrossDays` ignores S4's whole/half link** and
  cross-class units with more than 5 blocks. 3 whole + 3 per half needs 6 days
  and is not flagged (`Validation.scala:209-229`). Confirmed (probe).
- **D10 (medium). S5's assumptions are never validated**, although RULES says
  they should be. Equal hours with different block shapes passes, and the
  exporter's pairing then silently drops a lesson. Confirmed (probe).
- **D11 (medium). `groupBalance` marks unequal half hours per subject as
  Blocking**, contradicting S2, which allows an unmatched half lesson at a day
  edge (`LessonLine.scala:159-171`). Advisory only, since nothing gates on it.
  Confirmed.
- **D12 (low). Settings can be relaxed past T5.** No caps of 1, 2 and 4, and
  the database default run length is 2 (V2), against "never 2 in a row".
  Together with F14 and A12, settings validation needs one pass.
- **D13 (low). `roomCapacity` counts PE and tuition rooms as supply for
  ordinary lessons**, and omits tuition hours (`Validation.scala:149-162`).
  Confirmed.
- **D14 (low). PlanSheet:**
  - writes teacher names, the room number and `madeBy` unescaped, so a code
    containing `<script>` runs when the sheet is opened;
  - shows a double only in its first row, which reads as a window.

  Confirmed (probe).
- **D15 (low). One overloaded class gives three blockades**, naming halves
  that do not exist (`Validation.scala:94-140`). Confirmed.
- **D16 (low). PlanLayout defaults a stale block index to length 1**, so an
  edited line makes a plan look complete (`PlanLayout.scala:80`). Plausible.
- **D17 (test gaps):**
  - R3b, R3c, R3d, R3, R12 and R14 are untested;
  - no test with cross-class entries, a block longer than 1, or R10 across
    halves;
  - `ValidationSpec.scala:280-290` is vacuous.
- **D18 (nit). Stale or orphaned comments:**
  - `Validation.scala:164-173`, `241-249`, `307`, `351-356`;
  - `Plan.scala:19`: `madeBy`;
  - `Plan.scala:36`: "one of the two";
  - `School.scala:37-39`;
  - `Teacher.scala:81` hard-codes days 1–5;
  - `TimeSlot.scala:41` allows a ninth slot;
  - `CrossClassUnit.scala:78-79` validates twice;
  - `specialistRooms` reports a soft requirement as Blocking.

## A — API and database (api/, repository/, migrations)

- **A1 (high). Deleting a teacher, room or room kind that anything points to
  fails with an empty 500.** The two-column foreign keys
  `(x_id, school_id) … ON DELETE SET NULL` null `school_id` too, which is
  NOT NULL, on Postgres 14. **Verified:** a rolled-back delete of a teacher on
  a lesson line raises "null value in column school_id of relation
  lesson_line". After an import almost every teacher is referenced, so Usuń
  never works. Same for a room that is somebody's home room, and a room kind
  a subject requires. `RoomRepository.scala:31-35`'s comment says the
  opposite. Fix: a migration to `NO ACTION`, plus explicit nulling in the
  delete transaction (Postgres 14 has no column list for SET NULL).
- **A2 (high; with I-side effects). Lessons vanish from saved plans.**
  `plan_placement` cascades on `lesson_line`, `cross_class_group` and
  `individual_lesson` (V12, V13), and `CrossClassUnitRepository.replaceGroups`
  deletes and re-inserts every group on each save (**verified**). Renaming a
  PE unit removes its lessons from the current plan and from history, while
  `unresolved` stays 0 and the stored "rules kept" is unchanged. A re-import
  empties every plan, and the current one points at an empty plan. Fix: drop
  those placement foreign keys (keep `plan_id`), update groups in place, and
  let PlanLayout count what no longer resolves, as designed.
- **A3 (medium). Bad input and most database errors become an empty 500, and
  nothing is logged.** There is no error handler (`Main.scala:69-79`), and
  `ApiError` maps only 23505. A wrong enum value, malformed JSON or an unknown
  school id gives "500 Internal Server Error"; the Polish decoder messages
  never reach the user. Fix: an error handler that maps decode failures and
  23503/23514/23502 to 4xx, and logs SQLState plus constraint name, never row
  data. Confirmed.
- **A4 (medium). Routes do not stay inside one school.** By-id
  updates and deletes use `WHERE id = $id` only, attendance ignores the school
  in the path, and seven routes have no school in the path. Harmless with one
  school and no logins, but the model cannot keep schools apart. Confirmed.
- **A5 (medium). Editing during a run throws the run away** (see F3, A2).
- **A6 (medium, test gap). Nothing here is tested against the database or
  over HTTP.** A1–A3 would each fail the first such test. Confirmed.
- **A7 (low). V17 hard-codes the `belfer.` schema**, so the promised
  one-setting schema change breaks startup. Do not edit V17 (checksum); note
  it, or fix it forward.
- **A8 (low). V12, V13 and V17 drop V9's rule that every cross-entity
  reference is scoped to one school**, and `PlanRepository.current` filters on
  `plan.school_id`.
- **A9 (low). Blocks are capped at 12 in the database and not in
  validation**, so 13 gives a 500.
- **A10 (low). `pool-size` does not size the Hikari pool**; it stays at 10
  (`Database.scala:15-18`).
- **A11 (low). The tuition room kind is seeded only for schools that existed
  when V13 ran**, and FET finds it by name, which the API lets anyone rename.
- **A12 (low). Small API faults:**
  - generating for a school that does not exist returns 202 and leaks a map
    entry;
  - a negative attendance is clamped to 0, twice, against its own comment;
  - changing a line's class is silently ignored;
  - the snapshot is read in about 10 separate transactions;
  - the Optimisation decoder turns a missing field into "off" (a stale tab
    clears `maxClassDaySpread`).
- **A13 (low). No authentication.** The API binds to 0.0.0.0 and compose
  publishes 8081 directly, bypassing nginx. Staff names are readable from the
  network. Plausible, depending on the network.
- **A14 (nit). Dead code and small items:**
  - `PlanRepository.delete`, `IndividualPlanRepository.replaceAll`, and
    `GET /schools/{id}/lesson-lines` (no caller);
  - the http4s client dependencies in BUILD;
  - no `logback.xml`, so logging is at DEBUG;
  - misplaced or duplicate comments in `application.conf`, `Main.scala`,
    V10, V12 and `BUILD.bazel:19-25`;
  - health served as text/plain;
  - class names sorted as strings.

## I — Importer (importer/, ImportRepository, ImportRoutes, anonymiser)

- **I1 (high, privacy; user to check). The anonymiser's comments may contain
  a real pupil's pseudo-class code.** `anonymise-arkusz.py` lines 173, 318 and
  328 give a case-pair example and say that reusing it would "republish a
  student's initials"; the fixture's own pair is in the same class. **Check
  against the original export.** If the codes are real, replace them with an
  obviously fake example and decide whether to rewrite history; they are in
  git since `1cc3600`. The real arkusz is not in `testdata/private/`, so this
  could not be checked here. (This file deliberately does not repeat the
  code.)
- **I2 (high). Individual tuition ignores the chosen weeks** and adds up every
  window (`ArkuszMapper.scala:274-277` filters `doc.assignments`, not
  `inRange`). Tuition for weeks 1–19 is imported into a 20–29 segment, and
  chained windows double the hours. The fixture's tuition all runs 1–38, so
  tests cannot see it. Confirmed path.
- **I3 (high; part of A2). A re-import destroys everything entered by hand**,
  and the preview says nothing:
  - teacher unavailability and limits, home rooms;
  - support teachers, block shapes, attendance;
  - the optional flag;
  - every saved plan's lessons.

  Fix: count these in the preview and warn or refuse, or upsert by code.
  Confirmed.
- **I4 (medium). The 20 MB upload cap does not limit memory**: the multipart
  decoder buffers the whole body first. Behind nginx the effective limit is
  1 MiB, not 20 MB (no `client_max_body_size`). Confirmed.
- **I5 (medium). Tuition subject codes skip `baseOf`**, so a tuition row on
  an `r_` subject is silently dropped. Confirmed.
- **I6 (medium). Fitting pairs all singles of a line into doubles at once**,
  not "just enough". Weeks 13–18 of the fixture get 6 doubles nobody asked
  for (`ArkuszMapper.scala:194-210`). Confirmed.
- **I7 (medium). Unresolvable references are not reported.**
  - An unknown subject gives a 500 at apply, after a clean preview; the
    rollback is atomic.
  - An unknown teacher or homeroom teacher is stored as NULL.
  - Database check violations give 500s.

  Confirmed.
- **I8 (medium, privacy). The anonymiser's roll "nudge" can be reversed.**
  It is derived from the published class code and the script is public, so
  the real roll is recoverable. Fix: noise from `os.urandom`, or a secret salt
  kept in `private/`. Confirmed (mechanism).
- **I9 (low). Week windows are chosen correctly only inside a suggested
  segment.**
  - Cross-class and PE rows are never collapsed by window: et4 and E23 follow
    one another and are folded as if simultaneous.
  - The sample week can be a shared boundary week.
  - Membership rows are left out of segment detection.
- **I10 (low). Segment detection reads a shared boundary week as both windows
  running.** Weeks 12, 19, 30 and 36–38 are in no offered segment, and the
  default first segment (1–4) leaves out a subject that starts in week 5.
  What TydzienKon means (inclusive, or the next window's start) needs
  pinning down.
- **I11 (low). Parsing:**
  - a missing end week defaults to week 1;
  - a fractional hour count parses as 0;
  - codes are not trimmed;
  - non-numeric or inverted week ranges are accepted;
  - the tuition count is computed and thrown away, and `replaces` hard-codes
    0 groups;
  - a 0-hour group drops a unit to 1 hour;
  - tuition can pick up a pseudo-class's group membership rows.
- **I12 (low, privacy). The anonymiser's `verify()` checks less than it
  prints**, and `--reduce-only` writes without verifying. The committed
  fixture is clean on inspection.
- **I13 (nit):**
  - misplaced or orphaned comments in `ArkuszMapper` (178-182, 302-306,
    421-426);
  - a dead `.max(1)`;
  - the "saved as singles" note uses lines from before fitting;
  - README names fixtures that do not exist, and states the real count of
    tuition records;
  - unused regex and dead branches in the anonymiser;
  - `deriveTeacherSubjects` ignores tuition.
- **I14 (test gaps):**
  - no tests for ImportRepository or ImportRoutes;
  - the mapper is tested only at 1–19 and 1–38, never on a suggested segment;
  - nothing covers tuition week filtering, `r_` subjects, minimal pairing or
    unknown references;
  - two `ArkuszSegmentsSpec` tests do not check what their names say.

## U — Frontend

The API contract was checked against the routes and encoders: no mismatches.
There are no native dialogs and no `dangerouslySetInnerHTML`, and `tsc -b`
passes.

  Nauczyciele, Zasoby and Zespoły.
  - Edit 1A without saving, save 1B: 1A's edit is gone.
  - The attendance grid saves on blur, so tabbing between its cells destroys
    what was typed and drops focus.

  Fix: show the gate only on the first load, and key row drafts on their data.
- **U2 (medium). Switching class quickly on Przydziały can show one class's
  lessons under another's name**, and edits then save to the wrong class.
  There is no staleness guard (`AllocationPage.tsx:63-84`). Confirmed path.
- **U3 (medium). Any failure loading the plan is shown as "no plan yet"**,
  inviting a needless multi-minute regeneration (`PlanPage.tsx:52-60`).
  Confirmed.
- **U4 (medium). Class overloads are reported twice**, once by the frontend
  and once by the backend (`useFindings.ts:29-37`). Confirmed.
- **U5 (medium). Most form controls have no accessible name.** Labels lack
  `htmlFor`; table inputs, sliders and searches lack `aria-label`.
  Confirmed.
- **U6 (medium). The homeroom-teacher list is empty until the validation
  report loads**, and on a school entered by hand it stays empty until
  Przydziały is filled (`ClassesPage.tsx:158`). Confirmed.
- **U7 (medium). Deleting a room type locks affected subjects out of

- **U8 (low):**
  - overlapping import previews race;
  - the same file cannot be chosen again after Anuluj;
  - default codes for new records collide after a deletion (409);
  - the tuition banner counts lessons but says hours;
  - the gap-run highlight hard-codes 2 instead of the school's setting;
  - decimals reach the server and come back as an English status line;
  - blocked hours past a shortened bell schedule are invisible but block
    saving;
  - the last run's banner reappears on every visit;
  - buttons stay clickable mid-request (double "Dodaj przydział" makes two
    lines);
  - overlapping reloads can show older data;

  - Szkoła's number fields snap back when cleared.
- **U9 (nit).** Stale comments:

  - UI text on `ResourcesPage.tsx:229`;

  Duplication: `run()` in five pages, about 12 copies of the error-message

## Docs this review contradicts

- **RULES §6, S3 row** says "only indirectly, through R1": not even that (D4).
- **RULES §6, P2 row** calls R17 "exact": exact per half only (D3).
- **RULES §6, S6 row** says "cannot be broken": nothing checks the bounds
  (D6).
- **`RoomRepository.scala:31-35`** says deleting a kind "nulls the reference":
  it fails (A1).
- **PlanLayout's design** (re-imports leave references counted as
  unresolved): the cascade deletes them instead (A2).
